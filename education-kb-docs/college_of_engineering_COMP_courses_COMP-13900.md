## Course Description

### Course Description

This course provides a comprehensive introduction to the principles and practice of operating systems design and system-level programming. Students will examine the fundamental abstractions that modern operating systems provide, including process management, memory allocation, file systems, and inter-process communication, while gaining hands-on experience writing programs that interact directly with the underlying system. Emphasis is placed on developing a rigorous understanding of how hardware and software interact at a low level, preparing students for advanced coursework in systems design and software engineering.

---

### Learning Objectives

By the end of this course, students will be able to:

- Explain the core responsibilities of a modern operating system, including scheduling, memory management, and I/O handling, and describe how these responsibilities are implemented in representative systems.
- Write system-level programs in C that make use of POSIX APIs for process creation, file manipulation, signal handling, and inter-process communication.
- Analyze and reason about concurrency and synchronization problems, applying techniques such as mutexes, semaphores, and monitors to design race-condition-free concurrent programs.
- Evaluate trade-offs in operating system design decisions, including those related to scheduling algorithms, memory allocation strategies, and file system organization.
- Debug and profile low-level programs using standard tools, demonstrating the ability to identify performance bottlenecks and resource mismanagement within systems software.

### Assessment Methods

| Component | Weight |
|---|---|
| Programming Assignments (5 total) | 40% |
| Midterm Examination | 20% |
| Final Examination | 25% |
| Written Design Project | 10% |
| Participation and Quizzes | 5% |

**Programming Assignments** are completed individually and submitted through the department's automated grading platform. Assignments cover topics including shell implementation, memory allocators, thread synchronization, and basic file system construction. Late submissions are penalized at a rate of 10% per day unless a documented extension has been granted.

**Examinations** are written, closed-book assessments administered in-person. Students are permitted one double-sided reference sheet of their own preparation for each exam. The final examination is cumulative and will be scheduled during the university's official examination period.

**Written Design Project** requires students to produce a detailed design document and retrospective analysis for a self-selected systems programming problem. The project is submitted in two stages — an initial proposal reviewed at mid-semester and a final report submitted during the last week of instruction. Projects must be a minimum of 2,500 words and include diagrams where appropriate.

**Participation and Quizzes** consist of short in-class or online quizzes administered throughout the semester to reinforce lecture material, along with an overall participation assessment based on engagement during discussion sections.
